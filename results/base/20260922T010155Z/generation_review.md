## 生成形态

| 静态检查 | HumanEval | MBPP |
| --- | ---: | ---: |
| `solution` 能被 Python AST 解析 | 82/164（50.0%） | 374/378（98.9%） |
| 完整程序有语法错误 | 82/164（50.0%） | 4/378（1.1%） |
| 语法错误中，重新编码后接近 512 token 上限 | 75/82 | 4/4 |
| 语法可解析但未通过完整测试 | 51 | 160 |

“接近 512 token”是对解码文本重新编码得到的近似判断；原始生成 token 数未另存。
HumanEval 的 prompt 已包含函数签名和 docstring，模型只需续写函数体。它经常在
正确或部分正确的函数体后继续生成新函数、示例或解释，最后截断在未闭合字符串、
括号或表达式中。HumanEval 有 78 条 completion 另起顶层 `def`，其中 70 条的完整
程序有语法错误；其中有些额外函数可能是合法辅助函数，不能把 78 条都叫作重复。

MBPP 的 prompt 是模块级三引号题目说明，模型需自行写出目标函数；该格式下语法
稳定得多，但仍有 160 条“语法正确、完整测试未通过”的题。69 条可解析结果还带有
模型自行编写的顶层 `assert`，它们也是生成代码的一部分。

## 对下一阶段的含义

Base 已能解决一部分 Python 函数题，尤其是 MBPP；可以保留它作为 SFT 实验底座。
SFT 后要重点检查 HumanEval 的语法可解析率和重复续写是否改善，同时看两套题各自的
完整测试通过率。当前 SFT 数据采用三引号题干加代码答案，更接近 MBPP 的输入形态；
因此 HumanEval 的格式差异是解释后续结果时必须单独观察的因素，不能只看合计分数。
